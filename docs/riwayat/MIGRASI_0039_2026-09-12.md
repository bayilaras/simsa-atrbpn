# Migrasi Neon 0039 dan penggunaan SIMSA mandiri

Migrasi `0039_shared_rate_limits` berhasil diterapkan ke database Neon yang dipakai SIMSA pada 12 September 2026. Hasil migrator: **satu migrasi diterapkan, total 40**. Pemeriksaan sesudahnya selesai pukul **19.18 WIB**, dan query readiness dari source terbaru lulus pukul **19.20 WIB**.

Pengguna mengonfirmasi bahwa SIMSA harus berdiri sendiri. SRIKANDI menjadi acuan kemampuan dan pengalaman penggunaan, bukan layanan yang harus diintegrasikan. Tidak ada klaim bahwa seluruh fitur atau kualitas SIMSA telah dibandingkan dan terbukti lebih baik dari SRIKANDI. Tanda tangan elektronik tersertifikasi tetap di luar lingkup.

## Backup dan pemulihan

Backup baru dibuat sebelum migrasi, snapshot **19.12.15 WIB**, memakai helper historis 39 yang cocok. Backup sesudah migrasi mempunyai snapshot **19.20.03 WIB**, memakai salinan source 40 yang dibekukan. Keduanya terenkripsi, dengan kunci terpisah, disimpan privat di luar repository. Backup lama tetap tersedia.

Salinan helper versi 40 berisi 142 file source aktual, 12 hash helper, dan 40 entri manifest migrasi; hash dan ACL privat diverifikasi. Provenance mencatat HEAD `b25b418a41c88c4a913b148032f8e3dfa4934a69` beserta perubahan working tree, sehingga tidak menyatakan HEAD39 sebagai source schema40. Salinan berada di `output/fix-verification/recovery40-MC2Tg3/source`; pertahankan bersama backup dan prosedur pemulihannya. Dependency terpasang memakai junction setelah lockfile cocok; pada mesin pemulihan lain pasang dependency dari lockfile yang disimpan.

Autentikasi manifest, kecocokan helper/migrasi, ACL, GCM seluruh payload, dan header PGDMP diperiksa lokal. Pemeriksaan ini **belum membuktikan restore backup Neon nyata**. PostgreSQL Windows tidak menyediakan locale sumber `C.UTF-8` yang identik. `restore_verified` tetap `false`; salinan di luar workstation juga belum dibuat.

Jalur pemulihan diuji melalui 18 pemeriksaan PGlite: rollback transaksi sesudah DDL dan sebelum COMMIT, kompatibilitas readiness serta operasi aplikasi lama pada schema40, pengembalian schema yang dibatasi, dan upgrade ulang. Pemulihan aplikasi yang disarankan adalah memakai versi aplikasi lama sambil mempertahankan schema40. Jangan menjalankan migrator atau adapter backup versi39 terhadap database40.

Pengembalian schema hanya menjadi opsi khusus setelah seluruh API baru berhenti, tabel counter kosong, journal cocok, tidak ada sesi lain, dan tidak ada dependensi. SQL menggunakan `DROP RESTRICT` serta hanya menghapus satu baris journal yang identitasnya persis cocok. Prosedur tersebut diuji lokal dan tidak dijalankan pada Neon.

## Batas rilis aplikasi

Perubahan pada turn ini menerapkan database produksi dan menyelaraskan panduan SIMSA mandiri. **Frontend dan backend Vercel belum dideploy ulang**; versi aplikasi aktif tetap rilis sebelumnya dan kompatibilitasnya dipertahankan. Perbaikan source sebelumnya beserta perubahan panduan tetap berada di working tree untuk rilis aplikasi berikutnya.

Integrasi SRIKANDI bukan pekerjaan tertunda atau prasyarat rilis. Konfigurasi penggunaan mandiri: backend `SIMSA_APP_MODE=full`, `APP_PROFILE=internal`, `SRIKANDI_ENABLED=false`, dan `SRIKANDI_PRODUCER_ENABLED=false`; frontend `VITE_APP_MODE=full`, `VITE_APP_PROFILE=internal`, dan `VITE_FEATURE_SRIKANDI=false`. Metadata cloud membuktikan profil dan outbound nonaktif; nilai producer tidak diterbitkan endpoint publik. Tidak menghapus tabel, migrasi, atau riwayat integrasi yang sudah ada.
